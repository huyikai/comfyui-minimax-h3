# 预设故障与对策

按「先定位再重跑」处理。左边是现象，右边是先动哪里；动完再跑，跑完再检。

## 生成阶段

| 现象 | 对策 |
| --- | --- |
| ComfyUI 没起来 / 掉线 | 程序自己会 `restart_comfy()` 重启并等 180 秒，不用插手 |
| 显存 OOM，单条反复失败 | 重试两次后仍失败，先降 `--megapixels`（0.9 → 0.6）把这条跑出来，履历记明降过档；不要缩时长 |
| 单条排队超 45 分钟 | 程序判超时并重试。连续多条超时说明模型没加载好，手动重启一次 ComfyUI |
| 输出 mp4 过小（< 80KB）| 视为失败，程序会重试。持续如此检查 prompt 是不是空的 |
| 已有任务在跑 | `logs/run.lock` 里的 pid 还活着。同一时间只能一份。pid 已死会自动清锁续跑 |
| 磁盘低于 2 GB | 硬挡，清盘再开。低于 10 GB 只在开始邮件里警告 |
| 过夜渲染停在半条 | 电源计划会睡眠。开始邮件若写了「请改成从不」，把待机改掉再续跑；程序不改系统设置 |
| `no clip-*.md matching` | `--filter` 写的是脚本库里的相对路径，不是 Downloads 的目录名 |
| `no duration found in clip header` | clip 文件头缺 ``时长：`4.80s``，precheck 本该挡住 |
| 断点续跑没复用已有分片 | `megapixels` / `steps` / `--output-dir` 三者任一跟上次不同就不会复用，这是设计如此 |
| `已有任务在跑 pid=…` | 真有一份在跑就等它；单卡不能并行。那个进程已经死了的话锁会自动接管，不用手删 |
| `磁盘剩余 … 低于 2 GB，停下` | 清盘再来。低于 10 GB 只在开始邮件里警告，不挡 |
| `ComfyUI 连不上，停下` | 程序已经试过重启。手动跑一次 `start.ps1` 看报什么错；`--concat-only` 不需要 ComfyUI |
| 过夜跑到一半没动静，日志停在半条 | 多半是系统睡了。开始邮件里那条电源警告就是提前报这个，把待机改成从不再重发同一条命令续跑 |
| 批量里某条作品一直没渲 | 看 `logs/batch-status.json` 里它的阶段和原因，大概率是写稿阶段就跳过了（占号未生成） |

## 画面

| 现象 | 先动哪里 |
| --- | --- |
| 入画人数多了或少了 | Identity lock 只写本条入画的人；空位写成实物，不要写「某人不在画面」 |
| 说话的人嘴不动 | `<d>` 挂错人了，或这一拍被写成了旁观视角 |
| 跨条换了脸 | 同一个人在多条里的 Identity lock 措辞必须逐字相同，不要「润色」 |
| 跨段撞脸 | 两段用了同一套外观描述，改其中一段的年龄 / 发型 / 衣服 |
| 演的不是那件事 | 中文对照的节拍没写满，只剩摘要；补到能演（开口前 / 说的时候 / 说完） |
| 画面崩手、肢体错乱 | 确实无从下手时才换 seed，履历里注明「已排除脚本原因」 |
| 画面里烧出了汉字 | 英文里有引号包汉字，或出现 `subtitle` / `caption` 一类词，precheck 本该挡住 |

## 字幕与音频

| 现象 | 先动哪里 |
| --- | --- |
| 有语音无字幕 | 中文对照里这句缺起止秒数。无对白 clip 上报这条属正常，忽略 |
| 黄字全程挂着挡主体 | 段总表要标清每条的过去/现在；黄字只在块首出 2.5 秒 |
| 黄字取不到 | 段总表「屏幕字」表里解释性标题的写法要能被正则读到，用反引号包住 |
| 片尾字卡两行不齐 | 行尾逗号会把那行推左半个字，程序已自动去掉；仍不齐就是字数本来不等 |
| 成片比预期短 | `--concat-only` 时有分片缺失，程序会报 `missing rendered mp4s` |
| 完成邮件没有坏镜 | 程序合剪那封不改。遗留用 `notify.py leftover --label …` 另发，开头列未过检 |
| 响度与参考片差得远 | `logs/reference.json` 指的参考片对不对；程序已按 −12 LUFS 归一 |
| 接缝有静音空洞 | 15ms 以内忽略；持续偏大检查是不是某条分片尾部被截断 |
